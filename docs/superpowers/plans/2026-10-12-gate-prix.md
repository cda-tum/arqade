# GATE PRIX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task by task.

**Goal:** build GATE PRIX (`gate-prix/`), the behind-the-car quantum-circuit kart racer
specified in `docs/superpowers/specs/2026-10-12-gate-prix-design.md`. Its look is
`docs/superpowers/specs/2026-10-12-gate-prix-look.py`, the approved mockup.

**Architecture:**
- **Pure, tested rules:** `circuit.py` (gates, simulation, Hamming), `track.py` (segments,
  gate rows, boxes), `car.py` (driving), `race.py` (laps, arches, boosts, items, CIRCUIT
  CHECK, places), `bot.py` (CPU racers) and `match.py` (screens and states).
- **Drawing:** `road.py` is the pseudo-3D projection, `sprites.py` the size-cached sprites,
  and `render.py` the views, HUD and screens.
- **The risk goes first:** Task 2 builds the road renderer and benchmarks it before
  anything depends on it.
- **Playtest early:** the game becomes playable at the end of Task 5, before the art polish
  in Task 6.

**Tech stack:** Python 3.11, pygame 2.5.2, uv, pytest. Run commands from `gate-prix/`.

## Global constraints

- `requires-python = ">=3.11,<3.12"` and `pygame==2.5.2`, with no other runtime
  dependencies (no numpy).
- **Internal resolution:** 960x540, scaled exactly 2x by `pygame.SCALED`.
  - Each 2P view is 960x270 (P1 on top, P2 below); the 1P view is 960x540.
  - The art is smooth and anti-aliased, not pixel art.
- **Cabinet conventions** (`../AGENTS.md`):
  - raw buttons: A = 1, B = 2, Start = 9, Select = 8;
  - the stick: axis 0 steers, axis 1 brakes (pulled back) and drives the menus; deadzone
    0.25; read from the axis, never the hat;
  - Start + Select quits; Start pauses with RESUME and QUIT TO TITLE; 60 s idle returns to the
    title;
  - P1 is blue, P2 red, and CPU cars never use either colour;
  - the loader passes `--fullscreen --no-keyboard`, P1's dev keys avoid `l x r b y a`, and
    `--input-test` exists;
  - LF line endings.
- **The shared launcher:** `gate_prix.main.main(argv)` accepts `--fullscreen`,
  `--window-size`, `--no-keyboard` and `--fps`. Input goes through `pygame.event.get()` and
  `pygame.joystick.Joystick(i)`.
- **Fonts:** bundle DejaVu Sans Condensed Bold with its licence (from
  `/usr/share/doc/fonts-dejavu-core/copyright`). Bundle Press Start 2P and `OFL.txt` only if
  used.
- **Gate colours** (shared with the other games): H (248,192,40), X (232,64,72),
  Z (56,120,232), Y (168,80,216).
- **Race rules** (verbatim from the spec):
  - 6 cars; 3 laps; 8 gate rows per lap, so 24 slots; 1–3 arches per row; a random target
    from H, X, Y and Z with no gate twice in a row;
  - streak boost: +20% for 1.0 s, then +8% and +0.2 s per further right gate in a row, up to
    +60% for 2.0 s;
  - a wrong gate or an empty slot resets the streak;
  - CIRCUIT CHECK at the start of lap 3, over slots 1–16: boost (16 − d)/16 × 80% for
    1 s + (16 − d) × 0.25 s;
  - off-road top speed is 60%;
  - items are SPLIT (a mirrored clone for 2 rows, where either car counts) and QEC (the most
    recent wrong or empty slot becomes right); 2 item boxes per lap, weighted by place;
    A uses an item.
- **Commits:** gitmoji style, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  Stage explicit paths only.
- **Done means:** `uv run pytest -q` passes with pristine output, and
  `uvx --from 'ruff==0.15.22' ruff check src tests tools` is clean.

### Task 1: the scaffold and the circuit

**Files:**
- `gate-prix/pyproject.toml`, modelled on gate-drop's, plus `.python-version` and
  `.gitignore`.
- `src/gate_prix/`: `__init__.py` (a docstring only, **no SDL env side effects**),
  `__main__.py`, `config.py`, `circuit.py` and `assets/fonts/`.
- `tests/conftest.py`, which sets the dummy SDL drivers, `tests/test_circuit.py` and
  `tests/test_config.py`.

**`config.py`** holds every number from the global constraints (the boost table, the
CIRCUIT CHECK formula's constants, the laps, rows and car counts, off-road, deadzone),
`INPUT_CONFIG` in Planck Time's shape, and `IDLE_TIMEOUT`.

**`circuit.py`:**

```python
GATES = ("H", "X", "Y", "Z")
def apply(state: tuple[complex, complex], gate: str) -> tuple[complex, complex]   # exact 2x2 matrices
def run(gates: list[str | None]) -> tuple[complex, complex]                        # from |0>; None (empty slot) = identity
def bloch(state) -> tuple[float, float, float]                                     # for the car's orb
def random_target(rng, n: int) -> list[str]                                        # never the same gate twice in a row
def hamming(mine: list[str | None], target: list[str], upto: int) -> int          # empty counts as different
class Circuit:  # one car's slots: target, slots (str|None per slot, None until filled), streak, results
    def take(self, slot: int, gate: str | None) -> bool    # fill a slot (None = missed row); returns right/wrong; updates streak
    def qec(self) -> int | None                            # the most recent wrong/empty slot becomes right; returns it
```

**Tests:**
- known states: H|0> = |+>, Y|0> = i|1>, and H·H, X·X, Y·Y, Z·Z = I up to global phase;
- `bloch` gives |0> → +z, |+> → +x;
- targets: no repeats over 1,000 seeds;
- `hamming` with empty slots;
- `take`'s streak rules;
- `qec` picks the most recent mistake and returns None when there is none.

### Task 2: the track and the road renderer, benchmarked first

**Files:** `src/gate_prix/track.py`, `road.py`, `sprites.py`, `tools/benchmark.py` and
`tools/road_demo.py`, with `tests/test_track.py` and `tests/test_road.py`.

**`track.py`:** THE FRIDGE as data.
- **The segments:** a list of segments (length `SEG = 200` world units), each with a `curve`
  and a `hill` delta, making a closed lap of about 45 s at top speed. It has a mix of
  straights, sweepers, an S-bend and two "stage drops" (hills).
- **Gate row positions:** 8 per lap, never on a sharp curve, spaced so a row is readable
  ≥ 1 s ahead at top speed.
- **Item box positions:** 2 per lap.
- **Roadside sprite placements:** coax trees, attenuators and standoffs.
- **The racing line:** a lateral offset per segment.
- **Functions:** `segment_at(z)` and `lap_length()`.
- **Gate rows** are generated per race, from a seed and the target:
  - 1–3 arches at lateral offsets in [-0.8, 0.8] of the road's half width;
  - at least one gap of one arch width;
  - exactly one arch per row is the slot's gate, and the decoys are distinct other gates.

**`road.py`:** `RoadView(rect)` with `draw(surface, track, cam_z, cam_x, sprites_out)`, the
classic pseudo-3D road.
- It projects about 120 segments ahead from the camera.
- It accumulates curve into an x offset and hill into y.
- It clips by the "max y drawn so far", so hills hide the road behind them.
- It draws each segment as flat polygons, as in the look file: copper plate (alternating
  rings), rumble (gold and white), road (two tones) and a cyan centre line.
- It returns, through `sprites_out`, each visible sprite's screen position and scale,
  sorted far to near.
- It draws at the view's real size (960x270, or 960x540 for 1P) **without per-frame
  supersampling**, using pygame's polygon fills.
- Anti-aliasing the near segment edges with `pygame.draw.aalines` is fine if it is cheap.

**`sprites.py`:** `SpriteCache`.
- **Built once at start-up:** each sprite kind (coax tree, attenuator, standoff, the
  arch per gate in lit and unlit form, the item box, cars per colour, and the clone ghost)
  is drawn once at 2x in the look file's style and stored at ~24 sizes.
- **Drawing:** `blit(surface, kind, x, y, scale)` uses the nearest size.

**Backgrounds:** the plate overhead, the shield wall and the haze are pre-rendered per view
size and offset horizontally by curve for parallax.

**`tools/road_demo.py`:** a window that drives the camera round THE FRIDGE at top speed,
two views, with the stick and keys steering. Use it to see the road.

**`tools/benchmark.py`:** plain surfaces and `pygame.font.init()` only, because the cabinet's
SDL has no dummy video driver. It times 3,000 frames with two views, all roadside sprites
and a row of 3 arches in view, and 6 cars. It reports the mean, p95 and worst.
- **Desktop guide:** keep the worst frame ≤ 4 ms.
- **Write the numbers into the report.** The controller runs it on the cabinet when it is
  reachable.
- If the Pi then misses 16.7 ms, the fallback (640x360 at 3x) gets its own follow-up task.

**Tests:**
- the lap closes: the accumulated curve returns near its start, so the loop is drivable;
- gate rows: the counts, exactly one right arch, gaps, distinct decoys, and determinism per
  seed;
- projection: a segment further away is higher and narrower;
- the hill clip hides the segments behind a crest;
- the sprite cache holds every kind at every size and builds once.

**Commit:** `feat: :sparkles: GATE PRIX: THE FRIDGE track and the pseudo-3D road`.

### Task 3: driving and the race core

**Files:** `src/gate_prix/car.py` and `race.py`, with `tests/test_car.py` and
`tests/test_race.py`.

**`car.py`:** `Car(id, colour, lane_x)` with track position `z` (distance), lateral `x` (−1
to 1 is the road, beyond it off-road), `speed` and `boost` (strength and time left).
- `update(dt, steer, brake, segment)`:
  - auto-accelerates to `TOP_SPEED × (1 + boost)`;
  - off-road caps at 60%;
  - the stick steers;
  - curves push outward ∝ speed² × curve;
  - braking decelerates;
  - a brake held through a curve reduces the outward push (a light drift).
- **Bumps:** side overlaps push both cars apart, and a rear overlap slows the car behind.
- **Arch hits:** a car passes "through" an arch when its `x` is within the arch's half-width
  of the arch's offset as its `z` crosses the row.

**`race.py`:** `Race(seed, players: int, rng)`.
- **Building:** it builds the target (24 gates), the gate rows from the track, and 6 cars
  (players first, then CPU), and owns a `Circuit` per car.
- **Each frame:** `update(dt, controls)` steps every car, resolves bumps and resolves rows.
  Each row gives the car's arch (or none), then `Circuit.take`, and a boost from the boost
  table if right.
- **Laps:** lap counting, and the CIRCUIT CHECK when a car starts lap 3, which emits an
  event and applies the formula's boost.
- **Places:** ordered by laps then `z`. The finish order is kept, and the race ends when every
  player has finished (CPU racers still racing are placed by position).
- **Events:** `"right"`, `"wrong"`, `"miss"`, `"check"`, `"lap"`, `"finish"`, `"bump"`,
  `"box"` and `"item"`, for render and audio.

**Tests:**
- the boost table, exactly;
- a scripted car driving perfectly gets a 0-distance check and the biggest boost;
- a car that misses every row gets distance 16 and the smallest;
- off-road slowing;
- a curve pushing outward;
- a bump separating two cars;
- places;
- the finish;
- determinism per seed.

**Commit:** `feat: :sparkles: GATE PRIX: driving and the race rules`.

### Task 4: items and the CPU racers

**Files:**
- Modify `race.py`.
- Create `src/gate_prix/bot.py`, with `tests/test_items.py` and `tests/test_bot.py`.

**Items:**
- **Boxes:** item boxes at the track's box positions. Driving through one gives a random
  item if you hold none, weighted by place (the back gets more SPLIT and QEC; define the table
  in config). A box respawns after 3 s.
- **SPLIT:** a clone at `−x` (mirrored across the centre line) for the next 2 rows. A row
  counts as right if either the car or the clone takes the right arch, and wrong if
  either takes a wrong one with neither right. It has no physics of its own.
- **QEC:** `Circuit.qec()`. It does nothing visible if there is no mistake, but the item is
  still used.

**`bot.py`:** `Bot(car_id, skill, seed)` gives controls each frame.
- It steers toward the racing line, and toward the right arch's offset as a row approaches.
- It hits the right arch with probability by skill (the best about 85%). On a miss it aims at
  a decoy or the gap.
- It brakes into sharp curves at low skill only.
- It uses QEC when a mistake exists, and SPLIT when the next row has decoys.
- It applies mild rubber-banding through a speed multiplier by place.
- **Skills for the 4–5 CPU racers:** spread from 0.6 to 0.85.

**Tests:**
- each item's rules;
- box weighting by place, statistically over seeds;
- every CPU finishes every race over 20 seeds;
- the best CPU's right-gate rate is 80–90%;
- a perfect scripted player wins over 20 seeds;
- races stay close: the median gap from 1st to 6th is under 15 s.

**Commit:** `feat: :sparkles: GATE PRIX: items and the CPU racers`.

### Task 5: playable (match, input, a basic HUD, main, sound, deploy)

**Files:** `src/gate_prix/match.py`, `render.py` (basic), `input.py`, `display.py`,
`input_test.py`, `audio.py`, `main.py`, `deploy_batocera.sh` (mode 755) and `README.md`,
with `tests/test_match.py`, `test_input.py` and `test_main.py`.

**`match.py`:** TITLE, COUNTDOWN (3-2-1-GO), RACE, PAUSED and RESULT.
- **The title:** the stick picks 1 or 2 PLAYERS; A or Start begins; after 3 s untouched an
  attract race of 6 CPU racers runs.
- **During a race:**
  - Start pauses with RESUME and QUIT TO TITLE (the stick moves, A picks, B or Start
    resumes);
  - Start + Select quits;
  - 60 s idle returns to the title, also while paused;
  - the title waits for buttons to be released after QUIT TO TITLE;
  - a 60 s idle return also resets the title to 1 PLAYER.
- **The result screen:** A rematches, B goes to the title.

**`render.py` (basic, polished in Task 6):**
- 2P is two views (P1 on top), 1P a full view;
- the road and sprites from Task 2;
- the cars, with the clone drawn translucent;
- a simple HUD: the overlay wires as coloured boxes, the place, lap, streak and item;
- CIRCUIT CHECK and result text;
- the title and pause screens.

**`input.py`:** per player, steer (axis 0), brake (axis 1 pulled back), A, B, Start and
Select pressed and held, plus the keyboard fallbacks:
- P1: `e s d f` (steer `s`/`f`, brake `d`) and `q` for A;
- P2: the arrows and `.` for A;
- `--no-keyboard` disables them.

**`audio.py`:** synthesised effects (engine hum pitch ∝ speed, right gate, wrong gate,
boost, the check fanfare, the countdown, an item, a bump), silent if the mixer fails.

**`main.py`:** a fixed 60 Hz loop, `--fps`, and the launcher flags.

**Verification:**
- play 1P and 2P windowed with the keyboard;
- `--input-test` works;
- the README covers the rules, controls, setup, tests, tools, layout and deploying.

**Commit:** `feat: :joystick: GATE PRIX: playable`.
